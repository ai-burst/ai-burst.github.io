Breaking News

The math world (and Claude) made headlines this weekend. Both the AI Search roundup and AI Revolution are leading with extraordinary claims: an Anthropic mathematician says Claude helped prove the Riemann Hypothesis, and there's a reported unforced solution to Navier-Stokes — two of the hardest open problems in mathematics. Treat these as as-reported, unverified for now: the videos are roundups of claims that haven't passed peer review, and "Claude helped" almost certainly means a substantial human-led proof with AI assistance, not an AI-only result. What's genuinely interesting for you: the workflow behind it — how an LLM was used to explore proof strategies, verify lemmas, and catch gaps. That's a blueprint worth studying for your own agent/eval work.

Meanwhile, the AI market had its worst week in recent memory. Per the same roundups, Anthropic went public near a $2 trillion valuation, promptly slid back toward its IPO price amid protests over "AI that builds AI," and Nvidia lost roughly $900 billion in a single week, while Trump threatened a "tremendous tax" on AI data centers abroad. If accurate, this is the kind of volatility that reshuffles budgets: enterprise buyers get pricing leverage, and open-weight alternatives look comparatively safer than locked-in frontier API spend.

How to make the most of it:

  • Don't re-platform around math-breaking models yet. Until the Riemann/Navier-Stokes results are independently verified, treat any "Claude solves P vs NP" style claims as marketing. Do, however, dig into how the human+AI collaboration was structured — that transfers to your agent work.
  • Use the market dip to renegotiate or diversify. If you're paying for frontier model APIs, this is a moment to benchmark open-weight models (Qwen, Llama, DeepSeek lines) against your workloads and build a fallback path.
  • Watch GPU prices. Nvidia's crash and the bubble talk could mean cheaper used/refurbished hardware for your local LLM rig sooner than expected — see the budget GPU analysis in Worth a Skim below.

Work Watch — Snowflake, dbt & Cortex Code

Snowflake

Autopilot for sensitive data classification hit Public Preview. A new Snowflake release note announces that Autopilot now manages the timing of classification, reclassification schedules, and minimum object age — the stated goal being to optimize both performance and cost. This is an operational feature rather than a flashy one, but it matters for anyone running governed data platforms: it removes the manual tuning burden on when sensitive-data scans run, which is exactly the kind of thing that quietly bloats credit consumption if left to naive schedules. Worth enabling in a dev account to observe its reclassification cadence before rolling out.

dbt

dbt's AI agent is now resilient to flaky LLM providers. Per the dbt release notes, the platform agent now automatically retries transient LLM provider failures with exponential backoff, covering timeouts, rate limits, and server errors. For anyone driving dbt through AI-assisted workflows (model generation, natural-language-to-SQL, code review), this removes a class of nondeterministic failures that plague agent runs — a concrete reliability improvement you can verify in CI.

Multi-project agent search just got better. The same dbt release notes add get_related_models to multi-project agent contexts, enabling semantic search for related models across projects. If you use dbt's MCP/agent tooling, this should make cross-project lineage and "what does this model feed?" questions dramatically easier to answer contextually, rather than grepping for refs. (Additional coverage from the dbt platform release notes.)

Worth a Skim

What Really Happens Inside Your GPU When AI Answers — Cloud Codes, 12 min

  • The core thesis: to generate a single token, the GPU reads the entire model (e.g., a 16GB weight set) from memory, up to 100× per second — and the math cores spend most of their time idle, waiting on memory bandwidth, not computing.
  • Concrete data: the same card runs Qwen 3.8 27B at 78 tokens/s on llama.cpp but jumps to 144 tokens/s with multi-token prediction — a direct argument for why speculative decoding/multi-token prediction is a free-ish speedup on consumer hardware.
  • Key takeaway for you: when buying local-LLM hardware or tuning vLLM/Ollama, memory bandwidth, not TOPS, is the bottleneck — the RTX 5090's 3,352 AI TOPS are irrelevant if the memory subsystem starves them.

Best Budget Nvidia GPUs for Local AI — Cloud Codes, 21 min

  • The kicker: on the official llama.cpp 56-GPU speed ranking, an RTX 2080 Ti from 2018 writes 107.5 tok/s while the RTX 5060 Ti (2025, ~$800) manages only 90.9 tok/s on the same test.
  • The explanatory variable the video centers on: memory bus width, the spec buying guides gloss over. Wider bus = more bandwidth = more tokens/s for LLMs regardless of FLOPS.
  • Practical value: if you're spec'ing a local rig for 27B-32B models, a used 2080 Ti or a high-bandwidth mid-range card may beat a shiny "AI TOPS" flagship at a fraction of the price. This is the video to skim before any GPU purchase.

The Truth Behind the "Get Paid to Host NVIDIA GPUs" Viral Short — Cloud Codes, 2 min

  • The viral claim ("NVIDIA pays homeowners $1,000/month") is wrong on both counts: it's ~$150/month, and the homeowner is the one paying it.
  • The program is actually XFRA, a distributed data-center project from smart-panel maker Span (announced April 2026), with NVIDIA supplying GPUs — an outdoor box that plugs into your electrical panel.
  • Worth 2 minutes if you've seen the claim in your feed: a clean debunk of the economics of "passive income from AI hardware," and a reminder that the local-AI grift radar should stay on.
