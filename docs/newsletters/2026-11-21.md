## Work Watch — Snowflake, dbt & Cortex Code

### Snowflake

Snowflake's release notes surfaced a few small but genuinely useful updates in the last day. The most interesting is the new `AI_FUNCTION_OPTIMIZATION` experiment type: you can evaluate multiple model candidates on the same dataset and metric, then compare output quality and estimated cost in one workflow ([1](https://docs.snowflake.com/en/release-notes/all-release-notes)). That is a practical eval-driven model-selection pattern, and it removes some guesswork when deciding between Cortex functions or external model calls.

There's also an `AI_EXTRACT` accuracy improvement in preview as of Nov 20 ([2](https://docs.snowflake.com/en/release-notes/new-features)). If you use `AI_EXTRACT` for structured document extraction, this is a good moment to re-run your golden test set before trusting it in production. And `AI_COMPLETE` now supports Snowflake Decision as a preview ([9](https://docs.snowflake.com/en/release-notes/about)), which expands the set of decision-style workflows you can call through the same LLM-style API without leaving Snowflake.

On the pipeline side, a new Snowflake/AWS walkthrough shows a real-time Kinesis-to-Snowflake Iceberg pipeline built with the Snowpipe Streaming High-Performance SDK ([Snowflake + AWS walkthrough](https://medium.com/snowflake/build-a-real-time-kinesis-to-snowflake-iceberg-pipeline-with-snowpipe-streaming-high-performance-dd44dc9b7ce5)). If you're on AWS and standardizing on Iceberg rather than classic Snowflake-managed storage, this is a solid reference architecture.

Finally, the "Data Superhero" community piece is worth a skim for the career/visibility angle: what the program offers, and what teaching in public does for your own confidence ([Snowflake community blog](https://medium.com/snowflake/the-cape-fits-what-being-a-snowflake-data-superhero-offers-and-teaches-8f719a1e302c)). Not a feature change, but useful context if you're thinking about building a public data/engineering profile.

### dbt

dbt's November 2026 product update makes batch testing GA. According to dbt, v2 now combines `unique` and `not_null` tests into one query per test type, with internal benchmarks showing 40% lower runtime and 65% fewer warehouse queries ([dbt November 2026 update](https://courses.getdbt.com/blog/whats-new-in-dbt-november-2026)). If your test suite is running hundreds of tiny queries, this is a meaningful cost lever — and worth re-checking after you upgrade.

Two smaller dbt updates round out the morning. The Model timing table can now be filtered by Resource details, which helps you track down slow resources inside long-running models ([dbt release notes](https://docs.getdbt.com/docs/dbt-versions/release-notes)). And single-tenant dbt users get Cost Insights coverage for unit tests when filtering by Test resource type ([dbt platform release notes](https://docs.getdbt.com/docs/dbt-versions/dbt-platform-release-notes-gen)).

**Cortex Code:** no direct CoCo updates in today's material; the `AI_COMPLETE` Snowflake Decision preview above is the closest adjacent signal.

## Headlines

**llama.cpp pre-release b12606.** A new llama.cpp pre-release landed on Nov 21, 2026, and it removes the old gating and fallback logic for the fused lightning indexer — meaning the indexer is now always used ([llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases)). This is an internal runtime change rather than a user-facing feature, but if you self-build llama.cpp, it's worth testing your current model set before switching.

**Riemann Hypothesis claims are impossible to ignore — treat as unverified.** Levent Alpöge has published a remark saying that, working with Claude, he has discovered a proof of the Riemann Hypothesis, that the method extends to the Generalized Riemann Hypothesis, and that the arguments have been formalized ([remark PDF](https://alpo.ge/remark.pdf), [via Simon Willison](https://simonwillison.net/2026/Nov/20/levent-alpoge/)). Separate but related, Ravi Vakil shares a hurried announcement that Alessandro Masullo has a proposed proof of the Generalized Riemann Hypothesis — this one explicitly human-only, with no AI — that Brian Conrad has been reviewing for months ([Vakil's announcement](https://math216.wordpress.com/2026/11/20/hurried-announcement-alessandro-masullo-grh/), [via Simon Willison](https://simonwillison.net/2026/Nov/20/ravi-vakil/)). None of this is peer-reviewed yet; for LLM-watchers, the Alpöge claim is a striking real-world data point about Claude's usefulness in research, but it is firmly in unverified territory.

**Quiet day for open-weight releases.** There were no verified new Ollama releases ([Ollama releases](https://github.com/ollama/ollama/releases)), no fresh vLLM release note in the immediate window ([vLLM watch](https://localmodelwatch.tsuchitsuchi.com/en/2026/11/17/vllm-v0-34-0-released/)), and no clear new open-weight model launch in the gathered sources. The real engine-level action today is the llama.cpp pre-release above.
