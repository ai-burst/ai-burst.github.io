Work Watch — Snowflake, dbt & Cortex Code

Snowflake

The one solid primary-source item in today's material is a Snowflake release-note update: Cortex AI_COMPLETE now supports Snowflake Decision in public preview (1, 5). Snowflake describes it as a purpose-built model for high-throughput classification, scoring, and decision-making across large datasets — the kind of workload you would otherwise burn a lot of prompt tokens on with a general LLM. Practical read for me: benchmark it against your current Cortex calls on a labelled sample before trusting it, keep an eye on per-query cost versus quality, and remember that public preview features usually don't come with production-level guarantees. Also worth re-checking the release notes before the weekend, since the entry appears bundled in the wider weekly release feed.

Worth a Skim

Google's harness-based recursive self-improvement — AI Search (14 min)

  • The central claim is "continual RSI" applied to a harness — the scaffolding around the model — rather than to the model weights themselves.
  • The video walks through a self-improvement memory ("SIM") and compares SIM vs no-SIM in an ablation; the SIM variant wins in the presented setup.
  • It argues for a unified harness and claims the harness may matter more than the model behind it, which is a useful mental model for agent/tool-building even if the Google attribution is unverified.
  • No primary paper link is in the description, so classify this as channel-level reporting until a source lands.

Stanford's "16-token memory" claim — Cloud Codes (14 min)

  • The video dissects Stanford's Memorilla, which claims to compress hundreds of chats or an entire book into 16 memory tokens for a frozen Qwen3-8B.
  • It reports best-on-5-of-8 benchmark results and claims "27x faster" answers at 512 documents, which would be a major improvement for agent memory / KV-cache cost.
  • The description says the video also checks the official README and a public H100 test from Andris Gauracs — good instinct, but not a substitute for reproducing the results yourself.
  • Even if it doesn't replace RAG, this is the direction I'd watch for reducing context bloat in local-agent workloads.
