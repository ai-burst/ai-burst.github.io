## Work Watch — Snowflake, dbt & Cortex Code

### Snowflake

**AI_COMPLETE now covers Snowflake Decision (public preview).** Snowflake shipped a preview update adding `AI_COMPLETE` support for Snowflake Decision, its purpose-built model for high-throughput classification, scoring, and decision-making over large datasets. If you've been hesitant to wire classification workloads into Snowflake's managed SQL layer, this is a lower-effort path: one function call instead of a separate inference service. ([1](https://docs.snowflake.com/en/release-notes/new-features), [14](https://docs.snowflake.com/en/release-notes/2026/other/2026-11-20-ai-complete-snowflake-decision-public-preview))

**Also in preview: AI_EXTRACT accuracy improvements.** Snowflake's current release notes list accuracy improvements for `AI_EXTRACT` in public preview. If you're running document- or field-extraction pipelines into structured tables, this is a good moment to re-run your extraction eval set and see whether outputs improved without changing your SQL. ([1](https://docs.snowflake.com/en/release-notes/new-features), [3](https://docs.snowflake.com/en/release-notes/feature-releases-2026))

### dbt

**Remote dbt MCP server gets Gemini Enterprise support.** The November 2026 dbt release notes add support for the remote dbt MCP server with Gemini Enterprise, and the server is now available through the Databricks Marketplace. If you're standardizing AI-assisted dbt workflows on Google's enterprise models, this removes a setup barrier; if you're on Databricks, you can install it from the Marketplace rather than stitching together your own MCP bridge. ([2](https://docs.getdbt.com/docs/dbt-versions/release-notes), [4](https://docs.getdbt.com/docs/dbt-versions/dbt-platform-release-notes-gen), [9](https://www.getdbt.com/blog/whats-new-in-dbt-november-2026))

**dbt agent: automatic retry on LLM provider failures.** dbt also added an automatic retry mechanism for transient LLM provider failures in the agent. Network blips, rate limits, and 5xx-style server errors should now self-heal instead of failing a run — worth knowing if you run AI-assisted dbt jobs unattended. ([2](https://docs.getdbt.com/docs/dbt-versions/release-notes), [4](https://docs.getdbt.com/docs/dbt-versions/dbt-platform-release-notes-gen))

## Headlines

**A strong day for open-weight releases on the LLM releases changelog.** The standout is **Sber GigaChat 4 708B-A41B**, a 708B-total / 41B-active hybrid MoE model with native 1M-token context and MIT-licensed weights — the license alone makes it worth a closer look for commercial fine-tuning and serving experiments. ([13](https://www.llm-releases.com/changelog)) **Tencent Hy4** lands at 770B-total / 49B-active MoE with 1M context, with variants on Hugging Face, ModelScope, and GitCode under Tencent's license; it's another signal that the open-weight frontier is now pushing MoE at the same scale as the largest proprietary models. ([13](https://www.llm-releases.com/changelog)) And **AutoArk Edge0-145B** is the one I'd benchmark first on local hardware: an open MoE positioned as laptop-runnable at roughly 29GB memory use and 80+ tokens/s, with its own inference framework included. ## Repo Watchlist

### Snowflake

- **[lakefreight](https://github.com/sidbhaumik/lakefreight)** — bulk-move warehouse tables into open lakehouse files on cloud storage. Snowflake to S3 as Parquet today, readable by Databricks, Snowflake, Redshift, and BigQuery. I'd reach for it when old warehouse data needs to move to cheaper object storage without building a custom CDC pipeline.

### Local LLMs

- **[repdix-telegram-database-bot](https://github.com/CabreraDTM/repdix-telegram-database-bot)** — community-driven SQL orchestrator powered by a local LLM. It turns natural-language requests into SQL inside Telegram; useful as a reference for building local-LLM SQL agents in a chat interface.
- **[rumor-village](https://github.com/manuelgscom/rumor-village)** — 100 villagers driven by a fine-tuned local LLM in real time on one consumer GPU via llama.cpp, CUDA, or Vulkan. Offline, no accounts. Great stress test for local inference throughput and multi-agent simulation on modest hardware.
- **[LocalAI-VRAMReadyCheck](https://github.com/Powerdaalembic/LocalAI-VRAMReadyCheck)** — audits Windows PC VRAM, CUDA/Vulkan support, and RAM to recommend exact GGUF/Flux models for Ollama, LM Studio, or ComfyUI. Practical before you buy a GPU or download a 70B model blindly.

### LLM Development

- **[AgentInputLab-toolkit](https://github.com/Data-Designer/AgentInputLab-toolkit)** — task-aware input preparation and evaluation toolkit for LLM agents. I'd use it to standardize how agent prompts and context are prepared and scored across different eval sets.
- **[onebrain](https://github.com/0xTaoZ/onebrain)** — coding agents in one group chat with a shared brain. Only the agent you mention runs, and it reads only what it hasn't seen; the repo claims 31–81% fewer tokens. Directly relevant to token and cost optimization for multi-agent coding setups.
