Daily Signal — 2026-11-18

Breaking News

OpenAI shipped a new model pair: GPT-6.2 Astra and GPT-6.2 Sol. Astra is the new frontier model; Sol is the efficient, everyday-work model. Both are available in the API as gpt-6.2-astra and gpt-6.2-sol (OpenAI announcement, Simon Willison summary). The key pitch is work-per-token: OpenAI says both models deliver better results on demanding tasks with fewer output tokens, which means more within usage limits and lower cost at scale (official model video). Astra is aimed at complex professional artifacts — slides, spreadsheets, documents — while Sol is positioned as the efficient workhorse for everyday work. A Codex demo even shows Astra reconstructing a room from two video frames and turning it into an interactive Blender set (demo video). This is an API/frontier-model story, not an open-weight release, but the cost-per-output-token angle matters for anyone building agent pipelines.

Practical ways to use it:

  • Start an eval on gpt-6.2-sol for your high-volume summarisation, classification, and agent sub-calls. If quality holds, it should be cheaper per completed task.
  • Reserve gpt-6.2-astra for the hardest document/spreadsheet generation and complex agentic work — that is its stated target.
  • Upgrade your local tooling; Simon Willison shipped LLM 0.38 with support for the new model names (source).

Work Watch — Snowflake, dbt & Cortex Code

Snowflake

Spark Monitoring UI reached General Availability. Snowflake’s release notes say it is for monitoring and troubleshooting Snowpark Connect for Spark batch jobs and sessions directly in Snowsight (release note, new-features index). If you run Spark workloads against Snowflake, this is the first place to look when jobs stall.

Cortex AI Function Optimization went GA on Nov 16. It automatically searches across prompts and models, compares quality against estimated cost, and recommends more cost-efficient AI function implementations (release note). That is a direct lever for tuning Snowflake Cortex spend rather than doing the prompt/model search by hand.

Two practical Snowflake + AI-agent posts also landed on the official channel: an agent factory experiment that migrated PostgreSQL views and functions to Snowflake with parallel AI translators, scripted checks, and an independent AI reviewer (Snowflake blog); and a Claude Code + Snowflake research environment where SQL and an MCP server give agents access to versioned data in Snowflake (Snowflake blog). Both are good templates if you are building code-gen agents on Snowflake.

dbt

dbt’s November 2026 update is release-grade. dbt v2 is now GA across major warehouses; local unit tests are in alpha; batch testing can cut runtime and warehouse queries materially; there is a free dbt State plan; Wizard Desktop is in public beta; and dbt Charts now work in Claude and ChatGPT (dbt blog). For modelling and testing workflows, the local unit tests and batch-testing improvements are worth trialling this week.

Cortex Code

No fresh Cortex Code/CoCo release landed in the last 24 hours. The closest CoWork item remains the earlier deep-research/web feature from Oct 30 (release note). The Snowflake “agent factory” post above uses Claude Code rather than CoCo, but the parallel-agent plus independent-reviewer pattern maps directly to how you would orchestrate CoCo for migration work.

Headlines

  • Open-source Trainium inference engine appears. TrnRT, an inference engine for AWS Trainium, is open-sourced and currently serves GLM-5.3 Flash (FP8) on a trn2.48xlarge, with two instances per box behind a cache-aware router and 3.57M TPM on SemiAnalysis’s AgentX benchmark (GitHub). This is a signal that cheap open-weight serving on custom AWS silicon is becoming a practical option.
  • Simon Willison explores external sandboxes for coding agents. He worked with Prime Radiant on safer ways to sandbox code executed by agents, specifically to reduce the damage a mistake or prompt injection could cause when running local models (post). If you run local LLMs in agentic loops, this is the threat model to study.
  • llama.cpp news for the local/quantization crowd. A November recap points to llama.cpp v1.0.0 with FP8 KV-cache support, CUDA OCP FP8 support, and additional model support including Kimi-K3.1 (recap); v0.9.0 brought OCP FP8 E4M3 quantization support (recap). FP8 is the trend to track for faster local inference with lower VRAM.
  • “Not Everything Needs an LLM.” PostHog’s decision-model essay argues that deterministic decision models often beat LLMs at a fraction of the cost — a useful lens when designing pipelines that should route around model calls (article, HN discussion).
  • Datasette Lite was rewritten around service workers + Pyodide. Simon Willison’s browser-based Datasette now runs almost indistinguishably from the server-side app, using a carefully crafted URL against lite.datasette.io (post). It is a nice reference architecture for in-browser data tooling.
