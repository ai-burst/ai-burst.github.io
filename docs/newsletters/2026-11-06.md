## Breaking News

**OpenAI's autonomous exploit pipeline and GPT-6 Cyber dominate the day.** OpenAI revealed on November 4 that an autonomous AI cyber pipeline found **948 distinct ways for an unprivileged user to take root control of the Linux kernel** in a single run — though, per upstream kernel trackers, only **61 of those patches have actually landed so far** ([Cloud Codes](https://www.youtube.com/watch?v=d2N4rDNzMRc)). In parallel, OpenAI formally introduced **GPT-6 Cyber**, with Mozilla as a reference customer: the team used it to uncover previously unknown high-severity vulnerabilities in Firefox and ship fixes to millions of users ([OpenAI](https://openai.com/index/introducing-gpt-6-cyber/), [Mozilla case study video](https://www.youtube.com/watch?v=pXRZyOxbDL4)).

Meanwhile, **Sam Altman declared "the RSI era has begun,"** claiming OpenAI's agents now log three workdays for every one day its researchers put in, and that AI is "mostly smarter than top scientists" — while mathematicians publicly question OpenAI's Navier-Stokes proof and sentiment online turns against him ([AI Revolution](https://www.youtube.com/watch?v=YE2hf9WjUME)). Treat the RSI claims as company messaging rather than established fact; the exploit-pipeline numbers are independently checkable against kernel trackers.

**How to make the most of it:**
- If you're on Snowflake, the Expedition launch (below) means **CoCo agents and MCP servers are now the default integration surface** — worth a weekend spike to see what works for your stack ([Expedition summary](https://medium.com/snowflake/inside-snowflake-expedition-launch-summary-of-new-features-announced-5b049379fd2b)).
- **Watch your kernel patch cadence:** since only ~6% of OpenAI's 948 findings have landed upstream, distros and your fleet are still exposed to whatever the other 887 were. Prioritize patching any CVE that references the OpenAI pipeline.
- For local-LLM users: the **llama.cpp v0.9.0 FP8 file type** landed this week, so re-quantize your biggest models and measure the VRAM delta before committing to new hardware ([quantized.uk](https://quantized.uk/changelog/)).

## Work Watch — Snowflake, dbt & Cortex Code

### Snowflake
**Expedition 2026, day one, is a big one.** Snowflake positioned itself as "a unified engine for autonomous AI agents, real-time streaming applications, and conversational business intelligence" — the headline additions are a native **Business Ontology**, a **sub-15-second real-time streaming architecture**, and a **conversational BI tool** meant to replace legacy dashboards ([Expedition summary](https://medium.com/snowflake/inside-snowflake-expedition-launch-summary-of-new-features-announced-5b049379fd2b)). The philosophy: AI is only as useful as the enterprise context grounding it — so the ontology layer is the piece to learn first.

**Best practices for Semantic Views** are now documented with evaluation data. The article runs a 20-question test suite across architectures on Tasty Bytes and covers scoping, naming, sizing, and security for the governed semantic layer — practically a checklist for your next modeling review ([Semantic Views best practices](https://medium.com/snowflake/best-practices-for-scoping-and-organising-snowflake-semantic-views-6e2e2758b538)).

**Backups for Snowflake Storage for Apache Iceberg tables hit GA** (Nov 4) — a substantial data-protection feature if you've parked Iceberg tables in Snowflake-managed storage ([release notes](https://docs.snowflake.com/en/release-notes/new-features-2026)). Also in the same window: **HTML reports (Preview)** and, notably, **background runs plus extra supplementary tools for agents in the Snowflake-managed MCP server** ([release notes 10_39](https://docs.snowflake.com/en/release-notes/2026/10_39), [10_40](https://docs.snowflake.com/en/release-notes/2026/10_40)).

**Aimed at migrations:** the Snowflake AIM application now moves a SQL Server environment to Snowflake with AI agents doing extraction through validation; SSIS packages convert to **dbt** with AI analysis of conversion issues ([Snowflake AIM demo](https://www.youtube.com/watch?v=dzPbSSgNkHA)). If you have a legacy warehouse looming, this is the workflow to test.

Also worth a skim: **choosing how ML models move to production** on Snowflake — code, model, or hybrid promotion — a decision framework shaped by data access, training cost, and CI/CD readiness ([ML model promotion](https://medium.com/snowflake/choosing-how-ml-models-move-to-production-on-snowflake-code-model-or-hybrid-promotion-aca2ae322bb6)). And for agent work in life sciences, the **Gene Ontology OLS4 MCP server** integration shows how ontologies give agents a grounded context layer ([Ontologies + Snowflake AI agent](https://medium.com/snowflake/using-life-science-ontologies-from-a-snowflake-ai-agent-gene-ontology-and-the-ols4-mcp-c04fd5edc4ab)).

### dbt
**Two release threads to track.** dbt Core **2.0.11** (Nov 3) adds **BigQuery query reservation configuration at model and connection levels** — the most concrete feature update of the week ([dbt releases](https://github.com/dbt-labs/dbt/releases)). A day later, **dbt Core 1.13.0-rc1** shipped (Nov 4), so expect a stable 1.13 fairly soon ([dbt releases](https://github.com/dbt-labs/dbt/releases)). The patch release **v1.11.17** also fixes a `dbt deps` git credential issue on newer libcurl — annoying for teams using git packages ([v1.11.17](https://github.com/dbt-labs/dbt/releases/tag/v1.11.17)).

**On the methodology side:** dbt published an assessment framework for **organizational AI readiness**, structured around six dimensions to find where your data foundation limits AI adoption ([dbt blog](https://www.getdbt.com/blog/how-to-assess-your-ai-readiness)). It's marketing-adjacent but the six-dimension rubric is a genuinely useful conversation starter for platform reviews.

Meanwhile **CoCo Desktop v1.25.0** landed Nov 5; the changelog doesn't spell out what changed yet ([release notes](https://docs.snowflake.com/en/release-notes/new-features)). Check the full release notes before upgrading if you rely on pinned desktop versions.
