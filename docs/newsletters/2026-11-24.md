## Breaking News

**Z.ai releases GLM-5.4, its first loop transformer model** – the Chinese lab published [an overview of GLM-5.4](https://z.ai/blog/glm-5.4) and [Simon Willison wrote a summary](https://simonwillison.net/2026/Nov/23/glm-54/) on Nov 23. The headline innovation is a looped transformer architecture: a group of weight-shared layers runs multiple iterations per token, refining hidden states. This is the same trick used by Thinking Machines Lab’s Inkling 2 Mini (see Headlines) and promises better capability-per-parameter for on‑prem inference. GLM‑5.4 is aimed at coding and agentic tasks, not just chat. **How to make the most of it:** (1) Watch for a GGUF conversion and test it in llama.cpp once it lands – looped layers may change memory-access patterns compared to standard MoE models; (2) benchmark it against Qwen3.8 27B and similar open‑weights on your own agent tasks, because paper claims may not survive your eval; (3) if you’re running on budget GPUs, pay attention to active-parameter counts – looped transformers with low active parameters could be a sweet spot for 12‑16 GB cards.

## Work Watch — Snowflake, dbt & Cortex Code

### Snowflake

- **Pipeline Builder hits public preview** – a [one-minute demo video](https://www.youtube.com/watch?v=rlLXA63fvVE) shows how you can visually assemble Tasks, Notebooks, and ML Jobs on a canvas, schedule them, and then ship the result as versionable code. This is a big win for declarative pipeline development – you get the visual feel without losing git discipline.

- **Run Node.js and Python apps directly on Snowflake** – the [Snowflake developers video](https://www.youtube.com/watch?v=rEzpwkQbzik) walks through the new Snow App Deploy in the CLI: upload code, build, store versions, and get a live URL. Useful for embedding small services inside your data platform instead of managing a separate container fleet.

- **Gemini 4 Carbon and Hydrogen now in Public Preview in Cortex AI** – per [release notes](https://docs.snowflake.com/en/release-notes/2026/other/2026-11-12-gemini-4-carbon-hydrogen-preview), you have two new model tiers to choose from for VLM and heavy reasoning workloads. Carbon/Hydrogen are likely price/quality points you should test against existing GPT‑4‑class models.

- **Cortex Search Retrieve reaches GA** – the [Nov 18 release note](https://docs.snowflake.com/en/release-notes/2026/other/2026-11-18-cortex-search-retrieve-ga) means production RAG workloads no longer need to rely on preview APIs for fetching from vector indexes.

- **Cortex AI Function Studio goes GA** – [release notes](https://docs.snowflake.com/en/release-notes/2026/other/2026-11-19-copy-snowpipe-error-logging-check-constraints-ga) for Nov 19 give you a unified canvas to create, evaluate, and optimize Cortex AI Functions – worth trying if you’re tired of manually wiring prompts and evals.

- **AI_COMPLETE gains support for Snowflake Decision in Preview** – the [Nov 20 feature update](https://docs.snowflake.com/en/release-notes/all-release-notes) allows you to invoke decision agents directly from SQL, which could simplify some orchestration logic.

- **Agentic data foundation and manufacturing blogs** – Snowflake published guidance on [trusting AI agents with a governed data foundation](https://www.snowflake.com/content/snowflake-site/global/en/blog/trust-ai-agents-data-foundation) and on [preserving institutional knowledge in manufacturing](https://www.snowflake.com/content/snowflake-site/global/en/blog/ai-manufacturing-institutional-knowledge) using agents. Both are good source material for selling the “agents need governed data” story internally.

- **Production evaluation framework using dbt and Cortex** – a [Medium article](https://medium.com/snowflake/evaluating-ai-systems-in-production-on-snowflake-6fdac4f33988?source=rss----34b6daafc07---4) details a four-stage eval (prompt regression, bad inputs, hallucinated outputs, drift) built with dbt tests and Cortex functions. The example uses a support-ticket classifier. This is a concrete recipe you can adapt to your own LLM pipelines.

## Headlines

- **Inkling 2 Mini release** – Thinking Machines Lab shipped a 26B MoE with 3B active parameters that matches Qwen3.8 27B on paper, using a looped transformer (12 of 24 layers run three times per token). The [Codacus video](https://www.youtube.com/watch?v=X3ENZuTUS3k) tests it on real hardware and reports it actually runs on budget GPUs. This is the first serious open‑weight implementation of the looped‑transformer idea, so keep an eye on GGUF availability.

- **llama.cpp 1.0.0** – The local inference engine hit a major milestone with stable API, FP8 KV cache, MoE expert cache, and server hardening. [Full details](https://agentsunrise.pro/articles/local-inference-news-november-2026) are worth reading if you haven’t upgraded in a while – the FP8 KV cache alone can cut memory requirements significantly.

- **Ollama and vLLM releases** – Ollama’s late‑November cadence (v0.40.14–v0.40.16) adds new model support and changes OpenAI API default parameters; vLLM 0.33.0 moves to CUDA 13.0‑only, drops Medusa/MLP speculative decoders, and adds new models. Both are summarized in the same [local inference news roundup](https://agentsunrise.pro/articles/local-inference-news-november-2026).

- **Together AI adds DeepSeek-V4.1-Flash-1017-fast** – the fast serving tier now supports 1,000,000 context length, FP8 quantization, function calling, and structured outputs. See the [changelog](https://docs.together.ai/docs/changelog?ref=okapi.bot) for exact availability.

- **“LLM agents work for their parent companies, not for you”** – a [thoughtful essay](https://michaelharley.net/posts/2026/11/01/llm-agents-work-for-their-parent-companies-not-for-you/) argues that agent oriented around cloud providers will naturally favor those providers’ services and data. Worth reading before you commit to any vendor‑locked agent stack.

- **How should an LLM see a computer?** – [Greptile’s blog](https://www.greptile.com/blog/trex-computer-use) compares accessibility‑tree‑based perception with pixel-based for computer‑use agents, a decision that directly affects reliability and latency in your own agent projects.
